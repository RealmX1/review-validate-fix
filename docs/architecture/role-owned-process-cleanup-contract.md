# 角色结果与资源回收契约

Reviewer、Validate-Fixer 的 CLI 结果与后台资源退出是两个独立事实。有效的评审结果不会因清理缺证被改写为失败，也不会为了重试清理再次调用模型。`outcome.json` 保留业务结果，`role-owned-process-cleanup.json` 保存资源事实；业务结果事实和只读 `rvf analyze` 同时投影资源状态。

## 资源生命周期

角色复用 `retained_command_supervisor.py`，采用 `terminate_role_owned_processes_after_cli_exit` 契约。准备、补证、最终验证命令继续采用 `wait_for_background_work_or_register_separate_supervised_commands`，等待其已登记后台工作完成。角色自行启动的服务、浏览器应主动关闭；需要跨角色保留的工作须另行登记为受监督命令。

Worker、监督者和 CLI 继承同一把 execution 锁。Worker 崩溃后监督者继续等待 CLI，并在 CLI 退出后清理。监督者崩溃后仍存活的 CLI 保持锁，恢复方不会并发派发模型，也不会把健康 CLI 当作残留提前清理。CLI 退出后，恢复方从原生结构化输出补证结果，并独立回收已有归属证据的资源。

明确 Stop 先向角色监督者本身发送信号，由它发现并回收后代；外层撤销和 Worker 均不向其进程组发信号，以免提前终止 CLI、切断新后代的归属父链。监督者无响应时仅终止监督者，再按原生身份恢复清理。

监督者退出码单独保存为 `supervisor_returncode`，业务退出码只取同一次受监督派发保存的 `command_returncode`。后者缺失时保持 `unknown` 和不可重派，等待原生完成事实；跨配置也不能用另一个模型代替补证。锁上下文仅关闭自身描述符，不能显式解除 CLI 继承的共享锁；活跃输出的脱敏延至锁释放后的对账，避免替换 CLI 仍在写入的文件。

| 资源状态 | 含义 |
| --- | --- |
| `pending` | 所属 CLI 或监督者仍在执行 |
| `terminating` | 正在温和退出、有限升级或核验退出 |
| `exited` | 本次已登记资源的退出已核验，且无未解决观测缺口；或原生系统启动世代已改变 |
| `unknown` | 身份、观测覆盖或退出证明不足；保留结果与恢复条件 |

清理绑定控制目录、派发 `execution_token`、原生 PID/启动世代及系统 boot UUID（macOS `kern.bootsessionuuid`，Linux `/proc/sys/kernel/random/boot_id`）；macOS 身份同时核对 `unique_process_id`。清理只查询已登记身份、自有组和已核验父进程的后代链，不做全局扫描或进程名匹配。PID 被复用、身份缺失或超出 `pid_t` 范围时不发送信号。

每个仍匹配的资源先收到 `SIGTERM`，等待至多 2 秒后可升级为 `SIGKILL`，总核验预算为 3 秒。直接持有的 Popen 句柄可作为独立归属证据。发送信号只代表已请求终止，不能代表退出；资源仍存在或查询不可用时保存 `unknown`。清理单飞，重复恢复使用同一次派发的记录。

## 观测缺口与恢复

原生查询短暂失败时，当前观测最多连续尝试 3 次，间隔 50 毫秒；仍失败则保留活跃命令，按 1、2、4、5 秒的有界间隔探测恢复，不再一直等到 CLI 退出才补查。查询状态恢复为 available 不会抹除历史覆盖缺口。

macOS 的单次身份查询包含 BSD 启动身份与唯一身份两个原生读取。返回不完整且 errno 为 0 时，先有界重采一次完整身份；只有重查证明进程不存在或已成僵尸时才记为退出。权限错误、持续不完整或其他不可用仍为 unknown。该重查避免把可核验的瞬时竞争制造为新缺口，不能追溯清除已经保存的历史 gap。

当前空快照不能证明查询失败期间出现并脱离的后代已经退出。因此，观测发生过缺口时，命令结束及后续对账均保留 `unknown`；已证明归属的角色资源仍可清理。原生系统启动世代改变是等价的本地退出证据，可以自动解除该等待，且不会向新世代的 PID 发信号。

外层所有者的 `status=exited` 或周期性 PID 历史不能单独补齐缺口。系统只读核验与 run 首次登记执行同源的 Linux child-subreaper 回执：必须精确绑定任务、run、execution、launch nonce、控制目录、恢复 argv、boot、内外监督者及命令的完整原生身份，并同时证明派发前建立封闭、封闭连续性未丢失、根命令已结束且内核子进程观察为 `ECHILD`。满足时才以独立对账记录解除等待，原 supervision 与历史覆盖缺口保持不变；缺证、身份冲突、仍运行或仅含 PID/秒级启动时间的回执均被拒绝。只读恢复观测包含回执语义摘要，可信终态出现时可由现有编排器自动接续同一 run，不重派已完成角色。

资源清理恢复保存输入身份、下次探测时刻和次数；输入不变时每隔至少 30 秒重验，最多 3 次。原生身份或系统启动世代改变可立即接续。控制器恢复及读取角色完成状态时接续清理；只读恢复证据接口观察状态、原生身份、启动世代和到期预算，以便现有编排器检测恢复条件。只读 analyze 不执行清理。

原始 supervision、结果及失败历史保留，清理恢复写独立记录。资源未知状态不改变有效的语义结果，也不触发额外的 Agent 回合。

## 开销边界与验收

受监督命令由监督者按 50 毫秒间隔负责观测，外层等待不重复扫描同一棵树。未使用监督者的等待只向原生查询传入活跃身份，确认退出后将历史登记标为 inactive，保留审计历史；不为每个后代重复启动 `ps`。监督事实变化立即原子保存，静默心跳最多每秒一次。可执行文件摘要复用现有 1 MiB 分块 SHA-256 实现。

自动回归覆盖 Kimi/Codex 协议、Reviewer/Fixer、正常及非零退出、明确 Stop、Worker/监督者崩溃、持锁防重、恢复补证、温和退出后升级、PID 复用及身份缺失、观测故障和静默写盘预算。隔离实验还核验 npm → Vite → esbuild 的进程、HTTP 端口回收，并使用与修复前相同的 0/4/12 个后代及 800 条退出历史量测查询和 CPU。

周期观测无法证明一个从未被观察、已脱离所有登记链的后代归属；本契约保证安全回收已证明所属的资源，不把不可证明的逃逸路径宣称为已解决。完整隔离容器或内核执行范围约束不属于本次改动。
