## 新增机器采集成本

在独立 Git 仓库、Kanban 状态和隔离 HOME/CODEX_HOME/CODEX_SQLITE_HOME 中实际执行共用采集器。每条量测先运行既有起点解析器，再将其完整工作树观察传给采集器；采集器墙钟包含材料持久写入，不包含解析器、Python 启动或模型生成。

| 场景 | 新增统计 Git 命令 | 额外完整工作树捕获 | 采集器实测墙钟 |
|---|---:|---:|---:|
| Task Card 累计有效，首次 | 1 条 Dirty numstat | 0 | 25.079 毫秒 |
| 累计缺失，首次补采一个精确提交 | 2 条：Dirty + 精确 show | 0 | 44.849 毫秒 |
| 同一观察缓存复用，六次 | 0 | 0 | 0.616–2.174 毫秒 |
| 只有 Dirty 内容变化，两次 | 1，历史累计复用 | 0 | 22.394–23.724 毫秒 |

Task Card 汇总存在时，起点解析器另加 **1 条本地 base tip 核对命令**，用于识别统计失效；不能把它遗漏在总新增命令数之外。无该汇总时不加此命令。缺失提交每批最多 64 个精确 SHA，不查询全量 Git/Kanban 历史。量测仓库很小，数值不代表大型仓库的上界，也不与历史 Agent 的数十秒墙钟直接相减。

原始 JSON 同时保存解析器自身墙钟与采集器持久化前的内部量测，表中使用外层完整调用墙钟，避免漏算写文件成本。

复现命令：

```sh
python3 docs/investigations/2026-10-31-rvf-decision-facts/replay_and_measure_decision_facts.py \
  --output-file docs/investigations/2026-10-31-rvf-decision-facts/replay-and-measurement-results.json
```
